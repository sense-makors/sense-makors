Sense-Proto vs. ActivityPub

ActivityPub moves activities between servers. Sense-Proto, as these pages describe it, stores documents in a pod and authorizes each HTTP request. A pod does not become an ActivityPub inbox because it stores a note. The comparison below is about the shape of a write, using ActivityPub's published vocabulary and the OpenID PUT that Hewlbern/openID actually accepts.

Where a write goes

ActivityPubPod write on this site
Unit An activity, often a Create, posted to an inbox or outbox. An HTTP request to a resource URL. PUT /workspace/note.txt creates that resource.
Identity An actor URL on the sending server. A WebID. OpenID returns one that contains profile/card#me.
Authorization Server-to-server signatures and recipient lists on the activity. Bearer token, client credentials, or the X-Agent-* signature headers. Missing credentials on PUT return 401.
Delivery The sender's server posts the activity to each recipient's inbox. No inbox fan-out is performed by the note PUT. A later GET reads the resource back.

Worked example: the same sentence, two writes

An ActivityPub Create of a public note, following the activity vocabulary, addresses an outbox:

POST /users/ada/outbox HTTP/1.1
Host: social.example
Content-Type: application/ld+json

{
  "@context": "https://www.w3.org/ns/activitystreams",
  "type": "Create",
  "actor": "https://social.example/users/ada",
  "to": ["https://www.w3.org/ns/activitystreams#Public"],
  "object": {
    "type": "Note",
    "content": "Hello from Ada"
  }
}

The pod write that the OpenID functional test performs is not that activity. It stores the bytes at a URL the client chooses:

curl -i -X PUT http://localhost:3000/workspace/note.txt \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: text/plain' \
  --data 'Hello from Ada'

The response status for a new resource is 201. GET /workspace/note.txt returns Hello from Ada. Nothing in that exchange posts a Create to another server.

The ActivityPub vocabulary is specified at w3.org/TR/activitypub. The pod request is specified by the Solid protocol and implemented by OpenID. A side-by-side with ATProto is on Sense-Proto vs. ATProto.
