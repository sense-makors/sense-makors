Using SPARQL

OpenID (Hewlbern/openID) accepts SPARQL Update as a patch against a Turtle resource. It also has an in-process SELECT helper. Those are different operations. This page shows both, using the requests and queries in the repository tests.

Update over HTTP, SELECT in process

PATCH with Content-Type: application/sparql-update changes a resource. QuerySPARQL in internal/rdf/sparql.go runs a SELECT subset and rejects INSERT. There is no separate HTTP query endpoint in the functional test.

Worked example: PATCH a Turtle file

Write the starting graph with the Bearer token from Authentication. This is the request in test/functional/run.sh:

curl -s -X PUT http://localhost:3000/workspace/graph.ttl \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: text/turtle' \
  --data '<http://ex/a> <http://ex/b> <http://ex/c> .'

Insert one triple. The test expects HTTP 200, then a GET body that contains http://ex/d:

curl -s -D - -X PATCH http://localhost:3000/workspace/graph.ttl \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/sparql-update' \
  --data 'INSERT DATA { <http://ex/a> <http://ex/b> <http://ex/d> . }'

curl -s http://localhost:3000/workspace/graph.ttl

OPTIONS /workspace/note.txt returns Accept-Patch containing sparql-update. The same server accepts an N3 patch with Content-Type: text/n3. The test writes <http://ex/s> <http://ex/p> <http://ex/o1> . and then patches in <http://ex/s> <http://ex/p> <http://ex/o2> ., expecting 200 and the new object in the GET body.

SELECT against a graph in memory

QuerySPARQL applies a SELECT to a graph already parsed from JSON-LD. Default prefixes include schema: for https://schema.org/ and oid: for {base}/ns/records#. This query is the one in internal/rdf/sparql_test.go. It returns the row whose name contains openid and whose workType is identity-protocol:

PREFIX schema: <https://schema.org/>
PREFIX oid: <http://localhost:3000/ns/records#>

SELECT ?name ?workType WHERE {
  ?id a oid:AgentTrace ;
      schema:name ?name ;
      oid:workType ?workType .
  FILTER(CONTAINS(LCASE(?name), "openid"))
}

Passing INSERT DATA { <a> <b> <c> } to QuerySPARQL returns an error that mentions SELECT. Use HTTP PATCH when you need to write.
