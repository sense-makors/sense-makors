Building Client Apps

A client is any program that sends HTTP to a pod. OpenID, the server in Hewlbern/openID, accepts a Bearer token from POST /idp/login or POST /idp/register, a client-credentials token from POST /oauth/token, or an Ed25519 signature on each request. This repository also includes a Python Solid client under solid/.

What this page uses

The curl session talks to OpenID. The Python commands are the CLI documented in solid/README.md in sense-makors/sense-makors. They are different programs. Point each one at a pod you run.

Worked example: Bearer token write

Start the server with the commands on the Guides page, then register:

curl -s -X POST http://localhost:3000/idp/register \
  -H 'Content-Type: application/json' \
  -d '{"email":"ada@example.com","password":"testpass123","name":"Ada","createPod":true}' \
  > /tmp/openid-reg.json
TOKEN=$(python3 -c 'import json; print(json.load(open("/tmp/openid-reg.json"))["token"])')

That is the same read the OpenID functional test uses: it stores the response and prints the token field. Then create a resource and read it back:

curl -s -D - -o /dev/null -X PUT http://localhost:3000/workspace/note.txt \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: text/plain' \
  --data 'hello functional'

curl -s http://localhost:3000/workspace/note.txt

The create response is 201 and includes an ETag. The GET body is hello functional. A second PUT that sends If-Match: "deadbeef" returns 412. Sending Authorization: Bearer not-a-jwt returns 401.

Worked example: signed agent request

POST /agents with {"name":"Atlas"} returns token, agent.webId, agent.podPath, agent.publicKey, and privateKey. The agent profile is public at {podPath}profile/card. To write without putting the Bearer token on the request, sign METHOD|PATH|TIMESTAMP|WEBID with the Ed25519 private key and send:

PUT /{podPath}inbox/signed.txt HTTP/1.1
Host: localhost:3000
Content-Type: text/plain
X-Agent-WebID: {agent.webId}
X-Agent-Public-Key: {agent.publicKey}
X-Agent-Timestamp: {unix seconds}
X-Agent-Signature: {Ed25519 signature, base64url}

signed

The functional test expects 201 for that PUT. The same agent token can also PUT {podPath}inbox/job.json with Authorization: Bearer and Content-Type: application/json.

Python client in this repository

solid/README.md documents a CLI for a Solid pod. After the dependencies in that README are installed, a file round-trip looks like this (the URLs are the ones in that README; replace them with your pod):

python -m solid.src.cli file write https://example.org/my-pod/file.txt --input "Hello, Solid!"
python -m solid.src.cli file read https://example.org/my-pod/file.txt

Login against an issuer is a separate command, for example python -m solid.src.cli auth login --issuer https://login.inrupt.com/. That issuer is not the OpenID process on port 3000. For OpenID, use the Bearer flow above or the MCP URL http://localhost:3000/mcp.
