Data Modeling

Pods store documents. A WebID profile is a Turtle document. A note can be text/plain or Turtle. OpenID also stores saved chat transcripts as JSON plus a Turtle description. This page uses those shapes. The server is Hewlbern/openID.

WebID profile

Registration with "name":"Ada" publishes a profile the server will return from GET {podPath}profile/card. The functional test checks that the body contains the account name. A profile that matches the WebID page on this site looks like this:

@prefix foaf: <http://xmlns.com/foaf/0.1/> .

<#me>
    a foaf:Person ;
    foaf:name "Ada" .

The WebID is that document plus the fragment #me, for example the webId field returned by POST /idp/register, which contains profile/card#me. See WebID.

Worked example: a Turtle graph

This is the document the OpenID functional test writes before it patches another triple in. PUT it with the Bearer token from Authentication:

curl -s -X PUT http://localhost:3000/workspace/graph.ttl \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: text/turtle' \
  --data '<http://ex/a> <http://ex/b> <http://ex/c> .'

GET /workspace/graph.ttl returns that triple. The SPARQL page inserts a second triple into the same resource.

Conversation records

When a transcript is saved through OpenID, the server writes two resources under the account pod:

  • {pod}/{handle}/conversations/spark/{id}.json — JSON-LD transcript
  • {pod}/{handle}/conversations/spark/{id}.ttl — Conversation and Message triples

The containers conversations/ and conversations/spark/ are created first, with a trailing slash. The Turtle side uses dcterms:created, dcterms:modified, schema:dateCreated, per-message timestamps, foaf and schema roles, the owner WebID, and source=gemini-spark.

The in-server SPARQL helper is tested against JSON-LD like the following. oid expands to {base}/ns/records#:

{
  "@context": {
    "@vocab": "https://schema.org/",
    "oid": "http://localhost:3000/ns/records#",
    "workType": "oid:workType"
  },
  "@id": "http://localhost:3000/ada/records/traces/openid-agent-identity/abc.jsonld",
  "@type": ["CreativeWork", "oid:AgentTrace"],
  "name": "Wire MCP into OpenID",
  "workType": "identity-protocol"
}

That document is the fixture in internal/rdf/sparql_test.go. It is a record shape, not a second public write API. Querying it is covered on the SPARQL page.
