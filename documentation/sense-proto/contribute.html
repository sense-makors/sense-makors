Contributing

Two repositories hold the material this site describes. Documentation HTML lives in sense-makors/sense-makors under documentation/sense-proto/. The Solid server used in the examples lives in Hewlbern/openID and is licensed Apache-2.0.

Documentation

Each page is a static HTML file that links to its neighbours with relative URLs and loads css/styles.css. Adding a page means adding the file and a sidebar link on every page that shares this navigation, including the new file.

  1. Edit or add a file in documentation/sense-proto/.
  2. Keep new links on a page that exists in that directory, or on a URL you have opened successfully.
  3. Open a pull request against sense-makors/sense-makors.

Worked example: run the server tests

For a change to OpenID, clone that repository and run the tests named in its README:

git clone https://github.com/Hewlbern/openID.git
cd openID
go test ./internal/... ./test/...

The HTTP suite builds the server and then runs test/functional/run.sh:

go build -o /tmp/openid ./cmd/server
/tmp/openid -port 3460 -storage /tmp/openid-data -base-url http://localhost:3460 &
BASE_URL=http://localhost:3460 ./test/functional/run.sh

That script registers an account, writes /workspace/note.txt, patches Turtle with SPARQL Update, registers an agent, and checks /health and the well-known documents. Match new behaviour to those assertions instead of adding a route that nothing calls.

What to send

  • A documentation change that fixes a link should include the new href target in the same pull request.
  • A server change should include or update a functional assertion when it changes a status code or a JSON field the tests already read (token, webId, account.podPath, agent.webId, agent.podPath).
  • Issues for the server go to Hewlbern/openID issues. Issues for these pages go to sense-makors/sense-makors issues.
